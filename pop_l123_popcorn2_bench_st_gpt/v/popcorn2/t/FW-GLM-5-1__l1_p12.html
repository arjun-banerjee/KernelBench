# popcorn2: large-tier module centers (scripts/gen_popcorn2_centers.py).
# Source: KernelBench/level1/popcorn/12_DeepSeekMoEDispatchPermute.py

import torch
import torch.nn as nn

class Model(nn.Module):
    """
    Pack tokens into expert-major order for MoE execution.

    Each token is assigned to one expert and one slot within that expert's
    buffer. The kernel writes token activations into the packed dispatch layout.
    """

    def __init__(self):
        super().__init__()

    def forward(self, token_hidden: torch.Tensor, expert_idx: torch.Tensor, slot_idx: torch.Tensor, expert_offsets: torch.Tensor) -> torch.Tensor:
        num_rows = int(expert_offsets[-1].item())
        out = torch.zeros(num_rows, token_hidden.shape[1], dtype=token_hidden.dtype, device=token_hidden.device)
        for token in range(token_hidden.shape[0]):
            expert = int(expert_idx[token].item())
            row = int(expert_offsets[expert].item() + slot_idx[token].item())
            out[row] = token_hidden[token]
        return out

reasoning
Let me understand the task: 1. This is a MoE (Mixture of Experts) dispatch/permute operation 2. The forward function takes: - `token_hidden`: shape (num_tokens, hidden_dim) - token activations - `expert_idx`: shape (num_tokens,) - which expert each token is assigned to - `slot_idx`: shape (num_tokens,) - slot position within expert's buffer - `expert_offsets`: shape (num_experts + 1,) - starting offset for each expert's buffer 3. The operation: for each token, find its expert assignment, compute the row position using expert offset + slot, and copy the token's hidden states to that row in the output. 4. The output shape is (num_rows, hidden_dim) where num_rows = expert_offsets[-1] This is essentially a scatter operation where we're scattering tokens to specific positions based on their expert assignment. Let me design a CUDA kernel for this: 1. Each thread can handle one token (copy one row from input to output) 2. Each thread needs to: - Load expert_idx[token] - Load slot_idx[token] - Load expert_offsets[expert] - Compute output row = expert_offsets[expert] + slot_idx[token] - Copy token_hidden[token, :] to out[row, :] For efficiency, we should use coalesced memory access. Since we're copying entire rows (hidden_dim elements), we could: - Option A: Each thread handles one token, and within a warp, threads access consecutive tokens (coalesced on input), but scattered on output - Option B: Use a 2D kernel where each thread handles one element of the hidden dimension Given that hidden_dim = 160 and num_tokens = 4096, I think Option A (one thread per token, copying the entire row) might be simpler and efficient enough, but let me think about coalescing. The input reads from consecutive token rows within a warp, which is coalesced. The output writes to scattered locations based on expert assignments - this is inherently scattered due to the MoE nature of the problem. A better approach: launch (num_tokens, hidden_dim) threads total. Each thread processes one element: thread (t, h) reads token_hidden[t, h] and writes to out[expert_offsets[expert_idx[t]] + slot_idx[t], h]. This way each warp's threads handle consecutive elements within a token's hidden dimension, enabling coalesced memory access on both input and output reads and writes. The implementation uses a 2D grid where each thread handles a single element: compute the token index from blockIdx.y * blockDim.y + threadIdx.y and the hidden dimension index from blockIdx.x * blockDim.x + threadIdx.x. Check bounds, then load the expert index and slot index for that token, calculate the output row position, and copy the value directly without intermediate storage. The host function validates tensor dimensions, extracts the total number of rows from expert_offsets, allocates the output tensor, and launches the kernel with a block configuration of 32 threads per block across the hidden dimension and 16 threads per block across the token dimension, scaling the grid dimensions accordingly.
