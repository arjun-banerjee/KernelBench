import torch
import torch.nn as nn

class Model(nn.Module):
    """
    Fused **2D bidirectional cross-scan** block for robotics **SSM-hybrid** backbones
    (e.g. Vision Mamba / VMamba-style encoders on overhead maps, costmaps, or
    multi-sensor tiles).

    One forward fuses four fixed scan permutations of ``(H, W)`` into 1D sequences,
    applies a **shared depthwise Conv1d** (lightweight stand-in for a selective SSM
    along the scan), maps each result back to the grid, **sums** the four
    directional contributions, and adds a **residual**.

    Scan order (same spirit as 2D cross-scan / S2D):
      LR — row-major left→right, rows top→bottom  
      RL — row-major right→left per row  
      TB — column-wise top→bottom, columns left→right  
      BT — flip vertical then same as TB  
    """

    def __init__(self, channels: int, kernel_size: int=3):
        super().__init__()
        assert channels >= 1
        assert kernel_size % 2 == 1, 'use odd kernel_size for same-length conv1d'
        self.channels = channels
        pad = kernel_size // 2
        self.dw_conv = nn.Conv1d(channels, channels, kernel_size, padding=pad, groups=channels, bias=True)

    def _apply_scan_conv_unscan(self, x: torch.Tensor) -> torch.Tensor:
        """Shared depthwise conv along flattened 2D, then map back to (B,C,H,W)."""
        (B, C, H, W) = x.shape
        seq = x.flatten(2)
        y = self.dw_conv(seq)
        return y.view(B, C, H, W)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        """
        Args:
            x: (B, C, H, W) spatial features (map / image / fused tile).
        Returns:
            (B, C, H, W) after fused four-way cross-scan + residual.
        """
        (B, C, H, W) = x.shape
        assert C == self.channels
        acc = torch.zeros_like(x)
        acc = acc + self._apply_scan_conv_unscan(x)
        xr = x.flip(dims=(-1,))
        acc = acc + self._apply_scan_conv_unscan(xr).flip(dims=(-1,))
        xt = x.permute(0, 1, 3, 2).contiguous()
        (Bt, Ct, Wt, Ht) = xt.shape
        seq_t = xt.flatten(2)
        yt = self.dw_conv(seq_t).view(Bt, Ct, Wt, Ht).permute(0, 1, 3, 2).contiguous()
        acc = acc + yt
        xb = x.flip(dims=(-2,))
        xbt = xb.permute(0, 1, 3, 2).contiguous()
        (Bb, Cb, Wb, Hb) = xbt.shape
        seq_b = xbt.flatten(2)
        yb = self.dw_conv(seq_b).view(Bb, Cb, Wb, Hb).permute(0, 1, 3, 2).contiguous().flip(dims=(-2,))
        acc = acc + yb
        return x + acc

        super().__init__()
        self._impl = Model(channels, kernel_size=kernel_size)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self._impl(x)

For a kernel_size of 3 with padding=1, this is essentially applying the same 1D convolution to each channel independently. Let me think about how to optimize this with a custom CUDA kernel: 1. The current implementation does multiple memory operations (flips, permutes, flatten, view) which can be fused 2. The depthwise conv1d can be implemented efficiently in CUDA 3. We can potentially fuse all operations into one kernel Let me design the CUDA kernel: For each position (b, c, h, w) in the output, we need to: 1. Compute the contribution from scan 1 (LR): direct index mapping 2. Compute the contribution from scan 2 (RL): flip horizontal index 3. Compute the contribution from scan 3 (TB): transpose indices 4. Compute the contribution from scan 4 (BT): flip vertical then transpose Each contribution involves applying the depthwise conv1d along the flattened dimension. For a depthwise Conv1d with kernel_size K, padding P: output[n, c, i] = sum_{j=0}^{K-1} (input[n, c, i-P+j] * weight[c, 0, j]) + bias[c] Since this is depthwise (groups=channels), each channel has its own kernel. The H*W elements get flattened into a single sequence of length H*W, then the conv1d is applied to that sequence. So I need to unroll the flattening, apply the conv operation, and then reshape back—all of which can be handled in a single kernel pass. For the LR scan, element at (h, w) maps to position h*W + w in the flattened sequence. The RL scan (horizontal flip) reverses this: position h*W + w corresponds to (h, W-1-w), so the original element at (h, w) becomes h*W + (W-1-w). The TB scan (transpose) swaps dimensions, mapping (h, w) to (w, h) before flattening. The BT scan applies a vertical flip before the transpose. For each position, I need to compute contributions from all four scan directions and sum them. The tricky part is that the convolution output at a position depends on the input values in a neighborhood around that position in the scan order. A depthwise Conv1d with kernel_size=3 and padding=1 has an output the same length as input, where each output[i] combines the input[i-1], input[i], and input[i+1] weighted by the kernel. I'll work through a concrete example with H=2, W=3 to verify the indexing works correctly across all four scans. In the LR scan, position (h, w) = (0, 0) maps to index 0 in the output, but needs to access input[-1] which requires boundary handling. For the RL scan with horizontal flip, the input at position (h, W-1-w) gets processed through the convolution before being flipped back to position (h, w).
